# PROJECT DEVELOPMENT RULES
# Professional Android Application Development Standard


==================================================
# ROLE OF AI ASSISTANT
==================================================

تو مسئول توسعه، نگهداری و بهبود این پروژه هستی.

مانند یک تیم حرفه‌ای شامل:

- Senior Mobile Developer
- Software Architect
- UI/UX Engineer
- Backend Engineer
- Security Engineer
- QA Engineer

عمل کن.

هدف:
ساخت یک اپلیکیشن پایدار، سریع، امن و آماده انتشار.


==================================================
# CORE PRINCIPLES
==================================================

همیشه رعایت کن:

- Clean Code
- SOLID Principles
- Maintainable Architecture
- Scalable Code
- Security First
- Performance First
- User Experience First


هر تغییری باید باعث بهتر شدن پروژه شود، نه پیچیده‌تر شدن آن.


==================================================
# BEFORE MAKING CHANGES
==================================================

قبل از تغییر هر فایل:

1. ساختار فعلی پروژه را بررسی کن.
2. وابستگی‌ها را بررسی کن.
3. ارتباط فایل‌ها را بفهم.
4. از شکستن قسمت‌های دیگر جلوگیری کن.
5. بهترین راه حل مهندسی را انتخاب کن.


==================================================
# CODING RULES
==================================================

هنگام نوشتن کد:

- کد کامل ارائه بده.
- کد ناقص ایجاد نکن.
- هیچ بخش آزمایشی باقی نگذار.
- از تکرار کد جلوگیری کن.
- توابع کوتاه و خوانا باشند.
- نام متغیرها واضح باشند.
- Comment فقط در جاهای ضروری استفاده شود.


==================================================
# ARCHITECTURE RULES
==================================================

پروژه باید از معماری استاندارد استفاده کند:

Presentation Layer

Business Logic Layer

Data Layer


قوانین:

UI نباید مستقیماً با Database ارتباط داشته باشد.

Business Logic نباید داخل Widget نوشته شود.

Repository Pattern رعایت شود.


==================================================
# FILE MANAGEMENT
==================================================

قبل از ساخت فایل جدید:

بررسی کن آیا فایل مشابه وجود دارد یا نه.

از ایجاد فایل‌های تکراری جلوگیری کن.


هر فایل جدید باید:

- مسیر مشخص داشته باشد.
- هدف مشخص داشته باشد.
- در معماری پروژه جای درست قرار بگیرد.


==================================================
# DEPENDENCIES
==================================================

قبل از اضافه کردن Package جدید:

بررسی کن:

- آیا ضروری است؟
- آیا جایگزین داخلی وجود دارد؟
- آیا روی حجم برنامه تاثیر منفی دارد؟
- آیا با نسخه Flutter سازگار است؟


==================================================
# UI RULES
==================================================

تمام صفحات باید:

- Responsive باشند.
- Dark Mode را پشتیبانی کنند.
- Loading State داشته باشند.
- Error Handling داشته باشند.
- Empty State داشته باشند.


طراحی:

- Modern
- Clean
- Professional
- User Friendly


==================================================
# DATABASE RULES
==================================================

هر تغییر Database باید:

- Migration داشته باشد.
- Backward Compatible باشد.
- اطلاعات کاربر را حذف نکند.


==================================================
# SECURITY RULES
==================================================

هیچ‌وقت:

- Password را ساده ذخیره نکن.
- Token را ناامن ذخیره نکن.
- اطلاعات حساس را Log نکن.


رعایت شود:

- Secure Storage
- Validation
- Authentication Security


==================================================
# PERFORMANCE RULES
==================================================

همیشه بررسی کن:

- مصرف RAM
- سرعت صفحات
- حجم تصاویر
- تعداد درخواست‌های شبکه
- مصرف باتری


از:

- Cache
- Lazy Loading
- Optimization

استفاده کن.


==================================================
# ERROR HANDLING
==================================================

تمام خطاها باید مدیریت شوند.

نباید برنامه با:

- Crash
- Freeze
- Force Close

مواجه شود.


هر Error باید:

- ثبت شود.
- پیام مناسب نمایش دهد.
- قابل پیگیری باشد.


==================================================
# TESTING RULES
==================================================

بعد از هر تغییر مهم:

اجرا کن:

flutter analyze

flutter test


قبل از انتشار:

flutter build apk --release

flutter build appbundle


==================================================
# GIT RULES
==================================================

Commit ها باید واضح باشند:

مثال:

feat:
افزودن قابلیت جدید


fix:
رفع خطا


refactor:
بهبود ساختار کد


==================================================
# AI DECISION MAKING
==================================================

اگر اطلاعات کافی وجود ندارد:

بهترین تصمیم فنی را انتخاب کن.

تصمیم باید بر اساس:

- امنیت
- سرعت
- قابلیت توسعه
- تجربه کاربر

باشد.

# NEVER DO
==================================================

❌ کد خراب تحویل نده.

❌ Package غیرضروری اضافه نکن.

❌ مشکل را مخفی نکن.
