## ۲. خلاصهٔ طراحی و تصمیم‌های فنی

### ۲.۱ چرا نقاشیِ برداری و نه مدلِ سه‌بعدیِ بلادرنگ؟

صحنهٔ جزیره با چهار لایهٔ `CustomPainter` ساخته شده است: آسمان (ایستا)، دریا، خشکی، اتمسفر.

| گزینه | دلیلِ رد/قبول |
|---|---|
| مدل سه‌بعدیِ بلادرنگ (Flame/three.js) | **رد**: موتورِ رندرِ سه‌بعدی برای صحنه‌ای که فقط موج و آبشارش تکان می‌خورند، هم حجمِ APK را بالا می‌برد و هم روی گوشیِ ۱ گیگابایتیِ بازار هدف ریسکِ OOM دارد. |
| تصویرِ سه‌بعدیِ از پیش رندرشده | **ردِ مشروط**: هیچ داراییِ باکیفیت و دارای مجوز برای این صحنه در مخزن نیست و تولیدش به منبعِ هنریِ خارجی نیاز دارد. |
| **نقاشیِ برداریِ لایه‌لایه (انتخاب‌شده)** | **قبول**: صفر بایت به APK اضافه می‌کند، در هر نسبتِ تصویری بدون کشیدگی پر می‌شود، و عمق با ترفندِ ۲٫۵بعدی (تودهٔ صخره ← نوارِ ماسه ← رویهٔ چمن) ساخته می‌شود. |

**هزینهٔ فریم**: چهار لایه، هر کدام در یک `RepaintBoundary`؛ لایهٔ آسمان `shouldRepaint == false` است (یک‌بار رسم می‌شود). تنها لایه‌های متحرک، هر فریم چند `Path` و چند دایره می‌کشند (بودجهٔ ذرات: ۱۲).

### ۲.۲ سلسله‌مراتبِ تصمیم برای کودکِ بی‌سواد

```
        [پروفایل] [سطح] [صوت] [والدین]        ← کنترل‌های ثانویه، گوشه
                 لوگوی طلایی
              🐿️  فندقی (قهرمان)
          ▶︎  شروع بازی                      ← بزرگ‌ترین هدفِ لمسی
     [🎮 بازی]   [📖 آموزش]   [📕 داستان]     ← سه راه، فقط با تصویر
              نقشه جزیره                     ← همهٔ هاب‌های قدیمی
```

* هر سه مسیر نشانِ برداریِ کاملاً متفاوت دارد: **دستهٔ بازی** / **کتابِ باز با «ا» و «۱»** / **کتابِ بسته با ستاره**.
* برچسبِ فارسی هست اما شرط نیست: نشان‌ها به‌تنهایی معنا دارند.
* رنگِ هر مسیر اختصاصی است (بنفش / آبی / صورتی) تا حافظهٔ تصویری شکل بگیرد.
* کمینهٔ هدفِ لمسی ۶۰ پیکسل (بزرگ‌تر از استاندارد ۴۸) در `Island3DSurface` واقعاً اعمال می‌شود، نه فقط مستند.

### ۲.۳ تصمیم‌های فنیِ دیگر

| تصمیم | دلیل |
|---|---|
| نشان‌گذاریِ طلاییِ لوگو **برداری** | داراییِ اختصاصیِ «جزیره فندقی» در مخزن نبود (فقط `parsa_apps_logo`). یک `Text` با فونتِ کودکانهٔ موجود + سه سایهٔ برجسته، صفر بایت و در هر اندازه‌ای تیز است. |
| استفادهٔ دوباره از `AudioService.speakWord` برای راهنمای صوتی | این متد از قبل اولویت‌بندیِ درست دارد: صدای ضبط‌شده → TTSِ فارسی → سکوت. هیچ درخواستِ شبکه‌ای و هیچ صدایِ غیرفارسی اضافه نمی‌شود. |
| ذخیرهٔ تنظیمِ صوتی در `GrowthStore` | کنارِ بقیهٔ تنظیماتِ والد (`reduceMotion`, `colorBlindMode`) و با همان مکانیزمِ Hive؛ فیلدِ تازه با مقدارِ پیش‌فرضِ `false` و نوشته/خوانده/بازنشانی می‌شود. |
| دکمهٔ اصلی مسیرِ هدایت‌شدهٔ امروز را باز می‌کند | همان منطقِ `NextTodayButton.go`: `TodayPath.forChild()` → `pushNamed(task.route)`. اگر زمانِ بازی تمام شده باشد، یک برگهٔ مهربان نشان می‌دهد (و **نه** صفحهٔ والدین)؛ اگر چهار ایستگاه تمام شده باشد، `showTodayCompleteSheet`. |
| اسپلش: فقط «صحنه» اضافه شد | منطقِ `StartupCoordinator`، درصدِ واقعی، حداقل زمان، و مسیرِ امنیتی **دست‌نخورده** ماند. یک «لمس برای ردکردن» اضافه شد که فقط وقتی راه‌اندازی واقعاً کامل شده باشد کار می‌کند. |
| وابستگیٔ جدید: **هیچ** | `pubspec.yaml` اصلاً تغییر نکرده است. |

### ۲.۴ ایمنی و دسترس‌پذیری

* هیچ افکتِ چشمک‌زن، لرزشِ صفحه یا نورِ تند: بیشینهٔ شفافیتِ اتمسفر ۰٫۲۲ و چرخهٔ محیط ۱۴ ثانیه.
* `MediaQuery.disableAnimations` **و** `GrowthStore.reduceMotion` هر دو محترم‌اند (در صحنه، قهرمان و اسپلش).
* انیمیشن‌ها هنگامِ پس‌زمینه‌رفتنِ برنامه کاملاً متوقف می‌شوند (`WidgetsBindingObserver` در `IslandScene`).
* همهٔ کنترل‌ها `Semantics` با برچسبِ فارسی دارند (`شروع بازی`, `تنظیمات والدین`, `هدیهٔ روزانه`, `کتابخانه`, `پروفایل من`, سطح).
* پیامِ پایانِ زمانِ بازی مثبت و غیرتنبیهی است: «امروز استراحت … فردا دوباره با هم بازی می‌کنیم».
